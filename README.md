# Linda Schönfeldt - Portfolio Website

A performance-optimized portfolio showcasing my frontend development work. Built with React and focused on accessibility, responsive design, and a UX-minded approach.

**Live Site:** [lindaschonfeldt.com](https://lindaschonfeldt.com)

## 🎯 Project Overview

- **Responsive Design**: Mobile-first approach with fluid layouts
- **Accessibility**: Semantic HTML and ARIA attributes, aiming for WCAG compliance
- **Modern Stack**: React 18, Vite, Styled Components
- **Case Studies**: Data-driven case study pages, generated from JSON
- **Loading Screen**: Custom animated intro with real-time progress tied to chunk loading, shown once per session
- **SEO**: Per-page titles, meta descriptions and Open Graph / Twitter card tags

## 🏗️ Architecture

### Tech Stack

**Frontend Framework:**

- React 18 with Hooks
- React Router v6 for client-side routing
- Lazy loading with React.lazy() and Suspense

**Styling:**

- Styled Components (CSS-in-JS)
- Responsive design with custom media query breakpoints
- CSS variables for colors and spacing
- Transient props (`$prop`) to prevent DOM leakage

**Animations:**

- Framer Motion (loading screen only, removed from hero for performance)
- RequestIdleCallback for non-blocking operations

**State Management:**

- Zustand for lightweight global state (hamburger menu)

**Forms & Validation:**

- React Hook Form
- EmailJS for contact form submissions
- Google reCAPTCHA v2 for spam protection (see [RECAPTCHA_SETUP.md](RECAPTCHA_SETUP.md))
- Validator.js for email validation

**Icons:**

- lucide-react and react-icons

**Performance:**

- Web Vitals monitoring
- Route preloading on hover/focus
- Image optimization with Sharp
- Lazy loading and code splitting
- Terser minification (3 passes)

## ✨ Key Features & Implementation

### Performance

**Image Optimization:**

- Script generates WebP + original format in 3 sizes (400px, 800px, 1200px)
- Native lazy loading (`loading="lazy"`), with an `eager` prop for above-the-fold images
- Shimmer loading skeleton
- Falls back to the plain image if a size variant is missing
- `srcset`/`sizes` for responsive images

**Code Splitting:**

- Route-based splitting
- Vendor chunking (React, Router, Styled Components, Framer Motion)
- Current route preloaded immediately, other routes on idle (`requestIdleCallback`)
- Home chunk preloaded during loading screen to avoid Suspense fallback

**Loading Screen:**

- Only shown when the site is opened on `/`, once per session (`sessionStorage`)
- Never shown when navigating back to home, or when landing directly on another page
- Fails open if `sessionStorage` is blocked (private mode)

### SEO

- `Meta` component sets `document.title`, meta description, `og:title`, `og:description` and optionally `og:image` per page
- Default Open Graph and Twitter card tags in `index.html`, using `public/og-image.png`
- Case study pages use the project's `metaDescription` when set

**Terser Configuration:**

- 3 compression passes
- Console log removal in production
- Top-level mangling
- Dead code elimination

### Responsive Design

**Breakpoints** (`src/styles/devices.js`, all `min-width`):

```javascript
mobileS: '320px'
mobileM: '375px'
mobileL: '425px'
tablet: '768px'
laptop: '1024px'
laptopL: '1440px'
desktop: '2560px'
```

### Components

**Button:**

- Polymorphic (renders as `<button>` or `<a>` based on `url` prop)
- Variants: `primary`, `secondary`, `tertiary`
- PDF links get the `download` attribute automatically

**ProjectCard:**

- Four sizes: `small`, `medium`, `large`, `x-large`
- Shows video if `video` is set, otherwise image, otherwise `tree.svg`
- Cards in the same grid row stretch to equal height (tablet and up)
- `small`: stacked below 1440px, image beside text from 1440px, buttons span full card width
- `medium`: stacked (image on top)
- `large`: spans two columns, image beside text
- `x-large`: spans the full grid row, stacked (image on top), buttons in a row
- Buttons generated from project data via `utils/projectActions.js`

**ResponsiveImage:**

- WebP with PNG/JPG fallback
- Lazy loading with shimmer state
- Multiple size variants

## 🚀 Getting Started

### Prerequisites

- Node.js 18+
- npm

### Installation

```bash
git clone https://github.com/LindaSchonfeldt/portfolio2.0.git
cd portfolio2.0
npm install
npm run dev
```

### Available Scripts

```bash
npm run dev              # Start dev server (Vite)
npm run build            # Build for production → dist/
npm run preview          # Preview production build
npm run optimize-images  # src/assets → public/images
npm run lint             # Run ESLint
```

> `npm run build` does **not** optimize images. Run `npm run optimize-images` first when you've added or changed images.

## 📁 Managing Content

### Adding a Project

Add an entry to `src/data/projects.json`:

```json
{
  "id": 10,
  "slug": "my-project",
  "title": "My Project",
  "image": "my_project",
  "alt": "Short description of the image",
  "description": "What the project is and why it matters.",
  "metaDescription": "Short summary for search results and link previews.",
  "categories": ["Frontend"],
  "technologies": ["React", "Vite"],
  "github": "https://github.com/...",
  "netlify": "https://...",
  "size": "medium",
  "hasDetail": false
}
```

| Field                                   | Notes                                                                                   |
| --------------------------------------- | --------------------------------------------------------------------------------------- |
| `image`                                 | File name without extension. Leave out to use `tree.svg`                                |
| `video`, `videoPoster`                  | Optional. Shown instead of the image (see [VIDEO_SETUP_GUIDE.md](VIDEO_SETUP_GUIDE.md)) |
| `size`                                  | `small`, `medium`, `large` or `x-large`                                                 |
| `metaDescription`                       | Optional. Used as the case study page's meta description                                |
| `github`, `netlify`, `prototype`, `pdf` | Each one that is set becomes a button on the card                                       |
| `hasDetail`                             | `true` adds a Case Study badge and button linking to `/projects/:slug`                  |
| `current`                               | `true` shows the project in "What I'm Building" on the home page                        |

### Adding Images

1. Put the original image in `src/assets/` (e.g. `my_project.png`)
2. Run `npm run optimize-images`
3. Set `"image": "my_project"` on the project

### Under Construction

Add a project's `id` to `underConstruction.projectIds` in `src/data/siteConfig.json` to show a banner on the card and disable the Case Study button.

## 📊 Performance Metrics

> **Note on performance score:** The site intentionally uses a full-screen loading screen on the first visit to `/` in a session, which delays FCP and LCP by ~2.75s. This is a deliberate design choice and lowers the Lighthouse performance score for the home page. Other pages, and later visits in the same session, skip it.

**Lighthouse Scores (approximate):**

- Performance: ~40–55 (impacted by loading screen)
- Accessibility: 95+
- Best Practices: 100
- SEO: 100
